## Bugs found, root cause, and the rule that prevents the class

| PR | What the user saw | Root cause | Class → prevention rule |
|---|---|---|---|
| #30 | Nothing from the engine reached Chatwoot in low-memory mode | Rails runs as `web-prebuilt` there, but the engine calls `http://web:3000` | **Environment differs from the real wiring** → *Run-mode smoke check* |
| #31 | No way to open the connection panel after creating the inbox; API Provider blank | The panel was built and tested alone, but the settings page never added a tab for it | **Built but unreachable** → *Test the entry point* |
| #32 | "मैसेज बंद करो" not treated as an opt-out | Keyword list and tests used textbook phrases, not what customers type | **Thin test data** → *Realistic inputs* |
| #33 | No sidebar alert when the phone unlinked WaDesk | Reused Chatwoot's reauthorization flag, but its API output is limited to Meta embedded-signup inboxes | **Reused upstream without checking its consumers** → *Follow reused behaviour to what the user sees* |
| #34 | Switching QR ↔ pairing code while waiting said "removed from the phone" | A replaced link attempt reused half-registered credentials; WhatsApp answered 401 | **Lifecycle gap** → *Test every transition* |
| #35 | A rejected wrong phone's number stayed in the engine database | WhatsApp's library wrote a few rows just after the wipe | **Lifecycle gap** → *Test every transition* (including "after cleanup nothing comes back") |

The rules are part of the Definition of Done in the [handbook](../README.md#definition-of-done-every-task).
