## Findings and resolutions
1. **Pairing codes failed with the custom "WaDesk" label.** WhatsApp's code flow rejects custom device labels.
   Resolved by ADR-0007 (label per link method) in M1.6.
2. **A pairing code only works on the connection that requested it**, and WhatsApp replaces the connection every
   few minutes while waiting. Resolved in M1.6: `link_method: "code"` makes the engine request a fresh code on every
   connection and always return the current `pairing_code`.
3. **An unused pairing code expires with close code 401**, which the engine treated as "unlinked from phone".
   Resolved in M1.6: before a number is linked, 401 means the attempt expired — credentials are dropped and a fresh
   attempt starts within ~1 s. Verified on the real phone: code rotated after ~2 min 50 s, the session stayed
   `qr_pending`, and the rotated code linked successfully.
4. Baileys logs WhatsApp's normal post-link restart (stream code 515) at error level — to quieten in M5.1.
